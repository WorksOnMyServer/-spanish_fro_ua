# Оптимізація оперативної пам'яті — spain_bot

Архітектура і логіка бота (handlers/scheduler/crud/gemini_pipeline) не змінені.
Змінено тільки конфігурацію, залежності та Docker. Оригінал лежить у `spain_bot.tar.gz`.

## Результат (виміряно в Docker, повний стек)

| Компонент             | Було      | Стало     |
|-----------------------|-----------|-----------|
| Контейнер MySQL 8.0   | ~414 МБ   | ~112 МБ   |
| Контейнер бота        | ~210 МБ   | ~127 МБ   |
| **Разом RAM**         | ~625 МБ   | ~240 МБ   |
| Docker-образ бота     | ~650 МБ*  | 333 МБ    |

\* оцінка з build-essential, точно не міряв.

Перевірка: `docker compose up --build` на тестовій копії. БД ініціалізувалась,
планувальник стартував, бот дійшов до підключення до Telegram (у тесті фейковий
токен). Тест БД усередині контейнера пройшов: запис і читання уроку, 10 одночасних запитів.

## Що змінено

### docker-compose.yml
- MySQL: `performance-schema=OFF`, `innodb-buffer-pool-size=32M`, `max-connections=20`,
  менші кеші, `disable-log-bin` (−300 МБ RAM).
- Ротація логів для обох контейнерів (10 МБ × 3 файли). Раніше логи росли на диску без обмежень.

### database/connection.py
- `echo=False`: кожен SQL-запит більше не пишеться в лог.
- `pool_size=2, max_overflow=3` замість 5+10 з'єднань.

### requirements.txt: зафіксовано ВСІ залежності (47 пакетів, точні версії)
- `aiogram==3.28.0`. Версії 3.29+ при старті займають на 30–65 МБ більше.
- Точні версії означають, що кожна перезбірка дає той самий перевірений набір і нічого не зламається через нові релізи.
- Є `greenlet` (потрібен SQLAlchemy async) і `edge-tts 7.3.1` (виправлено 403).
- Видалено `openai` разом з мертвим кодом `generator/llm_pipeline.py` і `generator/schemas.py`.

### Dockerfile
- Прибрано `build-essential`, `libpq-dev` (це PostgreSQL), `netcat`, `curl`: вони
  не використовувались, а всі пакети ставляться з готових wheel-ів.
- `MALLOC_ARENA_MAX=2`: пам'ять менше «розповзається» з часом.

### Нові файли
- `.dockerignore`: не копіює в образ `.env`, архіви, `__pycache__`, `audio/`.
- `.env.example`: список усіх змінних оточення.

## Деплой на сервер
```
# 1. Зберегти поточний .env
cp /opt/bots/spain_bot/.env ~/spain_bot.env.backup

# 2. Розпакувати нову версію поверх (дані MySQL у volume не зачіпаються)
tar xzf spain_bot_optimized.tar.gz -C /opt/bots/
cd /opt/bots/spain_bot
cp ~/spain_bot.env.backup .env      # якщо .env перезаписався/зник

# 3. Перезібрати та запустити
docker compose build --no-cache app
docker compose up -d
docker stats --no-stream
```
Відкат: розпакувати `spain_bot.tar.gz` (стару версію) і так само перезібрати.
